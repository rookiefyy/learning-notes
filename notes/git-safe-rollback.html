开发工具 2026.11.24 示例笔记

在共享分支上撤销一次提交

当一笔修改已经进入共享分支，可以用 git revert 生成一条撤销提交。原提交会留在历史里，团队仍能追溯修改和撤销的原因。

确认目标提交

从共享分支的最新版本创建工作分支，确认工作区干净，再核对目标提交影响了哪些文件。这里的示例适用于只有一个父提交的普通提交。

git status --short
git show --stat 1a2b3c4
git show 1a2b3c4

创建撤销提交

把示例中的 1a2b3c4 换成确认过的提交 SHA。提交说明可以补上撤销原因，方便后来的人理解上下文。

git revert 1a2b3c4

后续提交改过同一处时，Git 可能提示冲突。确认这些后续改动应保留哪些，解决冲突并暂存后运行 git revert --continue。如果仍在处理冲突且决定取消，运行 git revert --abort。

检查撤销结果

用 git show HEAD 查看撤销提交，确认改动范围符合预期。运行受影响的测试，再通过团队常用的评审流程合入共享分支。
