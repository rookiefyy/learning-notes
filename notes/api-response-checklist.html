一份 API 响应检查清单

检查响应时，从调用方的下一步出发。它能否判断这次请求的结果、读出需要的数据，并在失败时采取正确的处理方式？

先看状态和结构

  • 核对 HTTP 状态码和 Content-Type 是否符合接口约定。
  • 检查必填字段、字段类型，以及调用方对缺失值和 null 的处理。
  • 对照契约确认返回值的单位、时间格式，以及列表的排序和分页行为。

给边界情况留一组样例

以查询笔记列表为例。若契约规定无匹配结果时返回空数组，就用一个没有匹配项的查询，断言响应仍能按同一结构解析。

{
  "items": [],
  "total": 0
}

再用有匹配项的查询检查数据内容，用无效的分页参数检查状态码和错误结构。如果调用方依赖稳定的错误码，也一并断言。

记录可复核的结果

保存请求场景、预期值和实际值，使用测试数据并省略认证信息。下次出现差异时，可以据此判断是接口契约、实现还是调用方处理发生了变化。
